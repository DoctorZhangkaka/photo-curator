# 已知限制（一期）

以下为按产品文档一期边界明确不做或实现上受限的内容。未列为“已实现”的能力不要假设存在。

## 功能范围

- 不做云同步、双向同步、多设备冲突解决；数据库只在本机。
- 不做连拍自动分组、相似照片对比、AI 选片、模糊检测、人脸识别。
- 不做客户/订单管理、约拍交付链接。
- 不做 RAW 调色、裁剪、任何图像编辑；不写 EXIF/XMP。
- 不支持视频、HEIC、PNG、GIF；只处理 `.jpg`、`.jpeg`、`.raf`、`.arw`、`.dng`。
- 不做永久删除；只有 macOS 原生废纸篓。
- 不自动清理已导出副本；取消精选不会删除历史导出文件。
- 不做任意拖拽配对编辑器；配对冲突需在 Finder 中改名/整理后重新扫描。
- 不提供“清空操作记录”。

## 相册识别

- 相册身份是“照片根目录下的一级文件夹路径”。在 Finder 中重命名相册文件夹会被视为新相册，原相册状态不会自动迁移（旧记录保留但指向不存在的目录，显示为扫描失败）。
- 只扫描一级相册目录、以及其下名称大小写不敏感的 `RAW`/`JPG` 一级子目录；更深嵌套中的图片不会导入，只在扫描报告中提示“未纳入”。
- 根目录下直接存在的图片不属于任何相册，只计入发现报告。
- 符号链接目录/文件一律跳过并记录，不支持通过链接把根目录外的照片纳入。
- 外部重命名照片主文件名会产生新的逻辑照片；旧记录按缺失保留，不保证保留原筛选状态。

## 元数据与 RAW

- JPG 元数据用 Pillow 读取；RAW 元数据依赖 ExifTool。未安装 ExifTool 时 RAW-only 照片的拍摄时间/相机信息显示“未知”，排序回退为自然文件名。
- 自动化测试夹具仍只包含合成 DNG 与伪造的 `.RAF/.ARW`，不包含真实相机 RAW，也不使用用户真实相册。
- 已用用户授权的一个真实富士 X-S20 RAF 相册做**只读**扫描/预览验证：975 个文件（568 JPG、407 RAF），407/407 个 RAF 由 LibRaw 打开成功，407 个配对组、161 个仅 JPG 组、0 冲突；抽样 RAF 解码、缩略图和预览正常。索尼 ARW 真实样本仍未验证。
- 其他机型/压缩方式仍取决于 rawpy/LibRaw 支持，个别新机型可能需要更新 rawpy/LibRaw。预览失败时界面会显示明确错误，不阻塞其他照片。
- RAW 预览使用 LibRaw 半尺寸解码后缩放到 2560px；`original-preview` 对 RAW-only 返回该高质量预览而不是全分辨率像素。
- 连拍/同快门多张的相似性不做识别。

## 文件操作

- 清理前必须通过预检；预检令牌默认 300 秒过期。执行时任何源文件变化都会使整批失败并要求重新预检（一期不提供“忽略异常继续删除其余”）。
- 每个逻辑照片是原子组：双格式组任一文件失败就尝试回滚已移动文件。若回滚也失败，会在操作记录和异常中心标记为严重失败，需要用户在 Finder 中核对实际位置；应用不会自动“修复”。
- 恢复依赖 macOS 废纸篓中仍存在原生 API 返回的位置。清空废纸篓、在 Finder 中永久删除或移动该文件后无法恢复。
- 恢复时若原路径已有新文件，拒绝覆盖并记录冲突；若原相册目录已不存在，恢复失败并提示从 Finder 废纸篓手动处理。
- 导出同名不同内容不覆盖、不自动加 `(1)` 后缀；冲突会保留在异常中心，需用户手动处理目标文件后重新导出。
- 导出采用“临时文件 + 硬链接发布”（`os.link`）保证不覆盖；若目标卷不支持硬链接（例如某些网络卷），该项导出会失败并记录，而不是降级为可能覆盖的写入。默认的 APFS 本地磁盘支持。

## 运行与并发

- 扫描、清理、导出是同步 HTTP 或进程内后台任务，没有持久化任务队列。应用退出会中断进行中的导出；下次启动会标记为「中断，需核对」，不会假装成功。
- 导出任务记录在内存中，页面刷新后可通过操作记录继续查看结果；不保存跨重启的进度百分比。
- 同一相册的扫描/清理/导出按相册锁串行；不同相册之间可以并行。
- 文件监听只覆盖当前打开的相册；切换相册后旧相册的外部变化在下次打开/重扫时处理。
- 大量文件同时复制时通过去抖减少扫描次数；不保证每一个底层事件都触发独立扫描，最终以完整校对结果为准。
- 预览缓存不自动按容量淘汰；可手动删除 `data/cache/previews`（只是缓存，删除安全）。

## 界面

- 目标为桌面浏览器；不保证手机触屏体验，但布局不假设单一分辨率。
- 一期界面中文；快捷键可在输入框/文本域/可编辑元素聚焦时被抑制。
- 照片列表使用游标分页（首屏 200 张）；切换排序/过滤时会尽量保持当前照片，如果它的新位置在已加载分页之外，会回退到当前列表第一张，而不是后台遍历所有游标。
- 浏览器全屏、缩放能力受具体浏览器限制；不提供图像编辑。
- 不提供多用户、登录、公网访问、移动端远程访问。

## 平台

- 仅支持 macOS（原生废纸篓依赖 `NSFileManager`）。Linux/Windows 上健康检查会显示废纸篓能力不可用，清理功能不可用；不会退化为永久删除。
- 需要在系统隐私设置中允许终端/启动器访问桌面或照片目录；否则相册会显示扫描失败或权限错误。
- ExifTool 未随项目安装，需要用户自行安装（可选）。

## 测试范围

- 真实 macOS 废纸篓集成测试只操作唯一命名的临时夹具并做恢复清理；不会测试真实相册。
- 真实 RAF/ARW 相机样本未包含在仓库中；相关解码依赖合成 DNG 与 rawpy 的 LibRaw 路径。需要验证特定相机型号时，请把合法样本放入本地测试目录手动运行。
- 性能目标在小尺寸合成图片上验证（1000 张逻辑照片）；真实高像素 JPG/RAW 的缩略图首次生成会更慢，且受 CPU/磁盘影响。
